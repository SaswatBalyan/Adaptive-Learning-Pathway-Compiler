Adaptive Learning
Pathway Compiler

A Flex + Bison + LLVM compiler for Path-Lang, a small language an educator uses to describe a student profile and adaptive branching. It lowers pathway.edu to verified LLVM IR and a program that prints the student's Alignment Score — in binary when a statement ends with ; b.

Run the demonstration

Two commands

From the repository root. The Makefile puts the MSYS2 toolchain on PATH itself, so this works from any shell.

repo root
make # build ./alpc make demo # compile & run examples/pathway.edu examples/pathway.edu compiles, verifies, runs -> 1111

Needs  flex 2.6 · bison 3.8 · make · g++ · LLVM 22 (llvm-as, opt, lli).  On Linux the distro packages suffice; the Windows setup is in docs/adr/0001.

Why 1111: the profile has performance = 60, so IF performance < 70 GOTO remedial is taken. The score is state = 0 + 15 = 15, and the program ended with ; b — so it prints 15 in binary. This is the PRD's worked example.

examples/pathway.edu
# Backward Design: every outcome is declared before a rule targets it.
OUTCOME remedial;
OUTCOME core;
OUTCOME advanced;

SET grade_level = 5;
SET performance = 60;

SET state = 0;
SET state += 15;       # the Fusion Function

IF performance < 70   GOTO remedial;
IF performance > 85   GOTO advanced;
IF performance < 1000 GOTO core; b

Walk the pipeline

Lexical analysis

Flex

scanner.l turns the source into tokens: the keywords, identifiers, numbers, the comparators, and the custom ; b binary-output terminator (SEMI_B).

02

Syntax analysis & Backward Design

Bison

parser.y is an LALR(1) grammar with zero conflicts. Each trace line is a reduction. The Backward Design rule — a GOTO may only target an already-declared OUTCOME — is enforced here.

./alpc --parse-trace examples/pathway.edu

reduction trace
outcome remedial outcome core outcome advanced set grade_level = 5 set performance = 60 set state = 0 set state += 15 branch performance < 70 -> remedial branch performance > 85 -> advanced branch performance < 1000 -> core binary-output

AST construction & RTTI

AST/RTTI

Three node kinds — ProfileSet, CondBranch, Outcome. The dump walks the tree through LLVM-style RTTI (NodeKind tag + classof + isa<>/dyn_cast<>) — no dynamic_cast, no -frtti.

04

LLVM IR code generation

LLVM IR

codegen.cpp emits one alloca per variable, load/add/store for the Fusion Function, and icmp + conditional br into a basic block per outcome. Every path converges on prog_end, which loads the score. The output passes opt -passes=verify.

./alpc --emit-ir examples/pathway.edu

pathway.ll · @main (excerpt)
define i32 @main() { entry: %state = alloca i32 store i32 0, ptr %state %state.cur = load i32, ptr %state %fusion = add i32 %state.cur, 15 ; state += 15 store i32 %fusion, ptr %state %p = load i32, ptr %performance %cond = icmp slt i32 %p, 70 br i1 %cond, label %outcome.remedial, label %after0 ⋮ prog_end: %score = load i32, ptr %state call void @print_binary(i32 %score) ret i32 %score }
05

Binary-output trigger & run

Run

Because a statement used ; b, prog_end calls @print_binary — an in-IR bit loop over @putchar. Execute the module with lli (or clang pathway.ll -o pathway).

./alpc --emit-ir examples/pathway.edu > pathway.ll && lli pathway.ll

console
1111

Binary conversion is checked for the PRD values: 0 → 0,  1 → 1,  15 → 1111,  255 → 11111111.

Malformed input never crashes

It rejects, it doesn't fall over

One clear line N: diagnostic, a non-zero exit, no stack trace. Ten invalid fixtures cover every rule.

tests/fixtures/invalid/backward_design.edu
OUTCOME core;
SET performance = 90;
IF performance < 70 GOTO remedial;
./alpc … ; echo "exit $?"
line 3: Backward Design violation: 'remedial' is referenced before it is declared as an OUTCOME exit 1

Toolchain. Flex 2.6.4 · Bison 3.8.2 · LLVM 22.1.8 · GCC 16.2 (MSYS2). Codegen targets the LLVM 22.x C++ API; the surface used is stable across many majors, and any drift is confined to codegen.cpp.

Language decisions. The scoring model — a single state variable, SET x += n as the Fusion Function, GOTO targeting a declared OUTCOME — is documented in SPEC.md §2 and docs/adr/0002.
